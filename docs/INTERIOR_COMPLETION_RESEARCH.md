- BuildModeLogics.CraftBuilding's wait-callback branch stores _cd, enters ScriptBuilding(mode4), clears/rebuilds the original last_build_desk craft list and calls native CraftAsPlayer. Native CraftReally spends materials; ProcessFinishedCraft sends the place event to the named FlowScript, then calls GameSave.OnFinishedCraft/End. - Script graphs provisionally replace/spawn the requested furniture before confirmation and preserve former object IDs. Beds/cupboards/walls use spawn/destroy; kitchen tables use two ReplaceWithObject mutations (home_cook_table and home_cook_stand). Ornament graph also observes rotate-left/right callbacks, so cycling a variation is not success.
- UpdateWhileScriptBuilding handles cancellation first: calls player.AddToInventory(_cd.needs) natively, then invokes public static on_cancel_while_script_building, exits/reopens the builder. The native AddToInventory Boolean is discarded by the host; do not invent guaranteed refund/capacity semantics. Script cancellation restores the prior object(s). Camera movement may delay downstream graph actions/end, so callback return alone must not be reported as full asynchronous script settlement.
- Apply invokes public static on_apply_while_script_building and closes script build mode without cancellation refund. The five graphs return camera/control and terminate their script; apply retains the provisional selection. CustomFlowScript.TerminateMe can also be reached after cancellation, so script termination by itself is not success. Callback identity and captured definition/owner/save must remain correlated across the early native finish and later outcome.

## One short native pass

1. Load a test save; retain any unrelated control goal. At the home builder choose an available kitchen-table variant different from the currently installed one. If unavailable choose a cupboard/bed/finish instead; record is automatic from selected recipe. Pin quantity1 and highlight its row.
2. F8: verify chosen name, click missing-resource grant if needed, close F8. Nothing is issued on load or panel opening. If inventory full, free space and retry the same button.
3. Start the normal native choice/preview, then Cancel. Allow camera/control to return. Prior furniture should be restored and goal/control remain. The observer records whether/how materials return; no manual counting is required.
4. Select the same variant again, Apply normally and wait for camera/control. Selected furniture should remain. Current production0.1.23 intentionally leaves this goal pinned even after Apply; the observer is passive and auto-removal comes only after a verified boundary and later candidate.
5. Exit the game normally and report completion. Tools collect logs, distinguish early craft markers from apply/cancel/script end and remove both sidecars. No reload/restart between cancel/apply or long list of39 tests is requested. A second readily available family/ornament rotation is optional supporting evidence, not a required material-gathering task.

A positive return can justify a dedicated production gate for the verified correlated callback family; it does not automatically authorize treating all scripts/events or every build-mode exit as success. If event/error/restoration ordering differs, keep production excluded and investigate only that gap.
